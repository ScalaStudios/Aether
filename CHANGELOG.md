# Changelog

All notable changes to Aether are recorded in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0, a minor version may change the API or the configuration; the notes for that version say how.

## Unreleased

### Added

- Quarantine for spam, phishing and malware. Mail Rspamd would reject, mail scoring 10 or more and mail with a ClamAV hit is accepted and stored by Aether instead of being rejected or filed into Junk. People see what was held for their mailboxes under **Quarantine** in Aether Mail, preview it without links, remote content or attachments, release it, delete it, request its release, or release it and allow the sender. Administrators review the organization's quarantine under **Administration → Quarantine**, filter and search it, release or delete in bulk, and set a policy per organization: who may release spam, high-confidence spam, phishing and malware, retention from 1 to 90 days (default 30), and daily, weekly or no digest emails, whose links need sign-in. Every release, deletion, request and policy change is in the audit log. Rspamd hands mail to the API on `/internal/quarantine`, which answers only private networks, and keeps its own action when the API cannot take it. See [Quarantine](documentation/quarantine.md).
- A **Mail queue** page under **Administration** for platform administrators: messages waiting in the Postfix queue with sender, recipients, status, last delivery error, arrival, next attempt and size, filtered by queue, sender, recipient domain or error. Retry now, hold, release and delete one message, a selection, or every message matching the filters, each recorded as a `mail_queue.<action>` audit event. Only the envelope is shown, never the content. The same is available as `GET /api/v1/admin/mail-queue` and `POST /api/v1/admin/mail-queue/{action}`. The Postfix image now includes `aether-postfix-api`, which serves the queue on internal port 8025 when `AETHER_POSTFIX_API_KEY` is set on the api and postfix containers; `scripts/setup.sh` generates the key, the Helm chart adds `postfixApiKey` to its Secret, and existing Compose installations add it to `.env` as [Mail queue](documentation/mail-queue.md#upgrading-an-existing-installation) describes. Without the key everything else works and the page says the queue is not connected. The Postfix image is now built with the repository root as an extra build context named `aether-source`.
- Two gauges for the Postfix queue, read every minute: `aether_mail_queue_messages` by queue and `aether_mail_queue_oldest_seconds`, the age of the oldest message not on hold. The `monitoring` profile loads `infrastructure/monitoring/alerts.yml`, which alerts when more than 100 messages not on hold stay queued for 15 minutes or one has waited more than 4 hours.
- Retention policies under **Administration → Retention**: delete messages from a folder once they are older than a number of days, or keep messages for at least a number of days, for the whole organization or one mailbox. A mailbox policy replaces the organization's for the same folder, and the longest keep policy counts. The API applies them once a day with doveadm `expunge`, Aether Mail shows the policy for the open folder ("Messages in Trash are deleted after 30 days"), and each change is a `retention_policy.*` audit event. Dovecot no longer sets `autoexpunge`; the 30-day Trash and Junk expiry is now a default policy that organizations can change. Keep for does not yet stop people or IMAP clients from deleting mail themselves.
- Protocol access per mailbox: Aether Mail, IMAP, SMTP submission, ManageSieve, and CalDAV and CardDAV can each be turned off, with defaults per organization for new mailboxes. Dovecot and the API enforce the switches for app passwords and access tokens, turning IMAP or ManageSieve off ends open sessions, and turning IMAP off for a shared mailbox removes its members' rights. App passwords have a scope, mail, calendar and contacts, or both; existing ones keep both. See [Protocol access](documentation/authentication.md#protocol-access).
- Local accounts can change their own password and turn on two-factor authentication under **Settings → Security**: an authenticator app (TOTP), security keys and passkeys (WebAuthn, used after the password), and 10 single-use recovery codes. **Settings → Where you are signed in** lists each browser with its IP address and last activity and signs out one or all others. Under **Administration → Security**, an organization can require two-factor authentication for its owners and administrators or for everyone; members who still need to set it up see only the setup screen. Administrators can list and end a member's sessions, and platform administrators can reset a password or remove someone's two-factor methods. `aether bootstrap-admin --reset-two-factor` does the same for an administrator. Accounts that sign in through an identity provider keep using the provider's two-factor settings. See [Local accounts](documentation/authentication.md#local-accounts).
- S/MIME and OpenPGP in Aether Mail, and password-protected messages for recipients outside the organization. Private keys are encrypted in the browser before they are saved, and a password-protected message is stored only as ciphertext. Organizations can turn each method off, allow it, or require it under **Administration → Encryption**. See [Encryption](documentation/encryption.md).
- Dovecot encrypts new Maildir messages at rest with a key derived from `AETHER_SECRET_KEY`. Existing plaintext mail remains readable. Use the resumable migration to encrypt stored messages on [Compose](documentation/installation.md#encrypt-existing-mail) or [Kubernetes](documentation/kubernetes.md#encrypt-existing-mail), and keep a protected backup of the original key.
- DMARC aggregate reports and SMTP TLS reports for other domains. Rspamd records the DMARC result of mail Aether receives, and once a UTC day has settled the API sends one aggregate report to every address in that domain's `rua` tag, including an external report address only when that address is in the same organization or publishes a matching authorization record. Outbound TLS sessions in the Postfix log become a TLS-RPT report for every domain that publishes a `_smtp._tls` record, except when outbound mail leaves through `AETHER_RELAYHOST`, because the log then shows the relay rather than the recipient's server. Both are sent from `AETHER_REPORT_FROM` (by default `dmarc-reports@` the verified domain of the mail host) through the authenticated submission path so Rspamd signs them with that domain's DKIM key, and `aether_reports_sent_total` counts the reports a collector accepts. `AETHER_SEND_REPORTS=false` turns both off. `AETHER_REPORT_ORG_NAME` sets the organization name in the reports.
- Domain DKIM key rotation via the API, with DNS checks before activation and a seven-day retirement window. Generate 2048- or 4096-bit RSA keys, add Ed25519 dual signing, or import an existing PEM key and selector. Active keys are flagged for rotation after 365 days. See [DKIM key rotation](documentation/installation.md#dkim-key-rotation).

- Signed mail delivery webhooks for delivered, deferred, bounced, received, and rejected messages. Organization administrators can manage suppressions under **Administration → Integrations** or through the API. Hard bounces add addresses automatically, and SMTP submission rejects suppressed recipients with a clear error.

- Live mail and notifications. Aether Mail keeps a server-sent event stream open and the API watches the relevant folders with IMAP IDLE, so new mail shows up without waiting for the 30-second poll. **Settings → Notifications** chooses new mail, calendar reminders and the folders that notify; Inbox is on until turned off. Browsers can register for Web Push, and a reminder on an event (`reminderMinutes`, stored as a `VALARM`) fires for the people who can see that calendar. VAPID keys are generated and sealed in the database when `AETHER_VAPID_PUBLIC_KEY` and `AETHER_VAPID_PRIVATE_KEY` are empty. iOS Mail push can send to a registered device when `AETHER_APNS_CERT_FILE` and `AETHER_APNS_KEY_FILE` are set, through `POST /internal/ios-push` with the Dovecot API key. The bundled Dovecot does not implement `XAPPLEPUSHSERVICE`, so the Mail app on an iPhone still cannot register itself. See [Notifications](documentation/notifications.md).

- JMAP for mail, calendars and contacts at `/.well-known/jmap` and `/jmap`. Sign in with an app password or an OpenID Connect access token; session cookies and API keys are refused. Mail is the mailbox behind Aether Mail, with stable folder and message ids, send, and the automatic reply. Calendars and contacts are the same records as CalDAV and CardDAV. Push is an EventSource that polls about every 15 seconds. See [JMAP](documentation/jmap.md).
- Labels and saved searches in Aether Mail. A mailbox can have 50 labels, each with a name and a color, stored on messages as IMAP keywords so Thunderbird and Apple Mail show the same tags. A message keeps its folder and can carry several labels. The folder list can show every message with one label, and a folder can be narrowed to one label. A saved search keeps the text, the unread, flagged and attachment filters, and an optional label, for one folder or every folder. Mail rules can add labels as mail arrives. Renaming a label keeps its keyword, changing its color updates Apple Mail's flag color, and deleting it removes the label from messages and from rules that use it.
- Undo send. Under **Settings → Sending**, choose Off or a hold of 5, 10, 20 or 30 seconds. Sending then keeps the message for that long and Mail shows **Undo**; undoing puts the draft back, including its Bcc. The hold is a scheduled message, so it still goes out if you close the tab, and only if your account is still active and you still have the send right it was held with. A time you pick in the scheduler is not held again. Off is the default, so existing mail is unchanged. Ctrl+Z or ⌘Z undoes the newest message still waiting. A read-only member who can send can cancel a scheduled message, which is what makes undo work for them. Migration 0064 adds the delay to each account and marks which scheduled messages are undo holds.
- One-click unsubscribe in Aether Mail. A message with a `List-Unsubscribe` header shows **Unsubscribe** in the reading pane, and **Newsletters** lists the senders of the latest inbox messages that carry one. With `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, the API sends the HTTPS POST itself (`List-Unsubscribe=One-Click`, no cookies, and it does not follow redirects). Otherwise it opens the https link, or sends the `mailto:` request from the mailbox when the caller may send. Links with a username, a scheme other than https, or a private or reserved address are refused, using the same check as webhooks; `AETHER_WEBHOOK_ALLOW_PRIVATE` allows http and those addresses. **Block** adds a mail rule that deletes later messages from that sender. Read-only access can use the one-click POST and the link, and cannot send a mailto request or add the rule.
- Remote images in Aether Mail stay hidden until the reader chooses **Show images** on that message or **Always show from this sender**, or an administrator sets the organization default to load them. Images that are shown are fetched by Aether's image proxy, which does not send the reader's IP address or browser, refuses private addresses, and drops known tracking images before requesting them. The default is under **Administration → Privacy** (`block` or `proxy`, migration `0065_remote_image_policy`). Allowed senders can be removed under **Settings → Remote images**. A message response includes `remoteImages`.
- Download links for large files, and organization limits for message size, inline attachments, the size at which a file becomes a link, the largest link, and the storage those links may use. Set them under **Administration → Limits**. Files over the threshold are uploaded and the message contains a link to `{public URL}/files/{token}` instead of the file. A link can have a password, which is never written into the message, and an expiry. Unsent links are removed after 30 days, and expired links are removed on the same schedule. The platform administrator caps every organization with `AETHER_MESSAGE_SIZE_LIMIT` (also Postfix's `message_size_limit`, default 50 MB), `AETHER_MAX_LINK_BYTES` (default 2 GB) and `AETHER_MAX_STORAGE_BYTES` (default 100 GB). The API accepts a request body for 30 minutes so a large upload can finish.
- Contact groups and shared address books. A group names people in one address book; choosing it while writing mail, or the write button on the group, addresses every member who has an email. Groups are stored as vCards with Apple's `X-ADDRESSBOOKSERVER-KIND:group` and vCard `KIND:group`, so they sync over CardDAV with the address book. Anyone can create an address book and share it with a person, and an organization administrator can share one with everyone in the organization, view only or editable, the same way calendars are shared. A shared book appears in CardDAV as `shared-<id>`, and a view-only share refuses changes. The main address book cannot be deleted. Migration `0067_contact_groups` records which cards are groups and who their members are.
- Mailbox export. A person downloads their mailbox from **Settings → Export mailbox**, and an organization administrator downloads any mailbox in the organization from **Administration → Mailboxes**. The export is a ZIP of `.eml` files or an mbox, for the whole mailbox or one folder, optionally limited to a date range, plus the owner's calendars (ICS) and contacts (vCard). It runs in the background. The download link expires seven days after the file is ready. Every export is an audit event `mailbox.export`. API keys cannot export mail.
- Deleting a mailbox removes its mail from the vmail volume. `DELETE /api/v1/mailboxes/{mailboxId}?graceDays=30` (from 1 to 3650) closes the mailbox and keeps the mail until then; `POST /api/v1/mailboxes/{mailboxId}/restore` brings it back. Omitting `graceDays`, or passing 0, deletes the mailbox and its mail immediately. A mailbox with `onHold` set is closed and its mail is kept. The console offers 30 days, 7 days, or now, and a hold switch.

- SCIM 2.0 provisioning for users: an identity provider such as Halo can create, update, deactivate and deprovision Aether accounts at `/api/v1/scim/<slug>`. New accounts get a mailbox when their address is on a verified domain and can sign in through the provider straight away. Turn it on under **Administration → Identity providers**.
- IMAP and SMTP submission accept OpenID Connect access tokens through `OAUTHBEARER` and `XOAUTH2`. The API checks each token with the provider's introspection endpoint, requires that it was issued to Aether, and checks mailbox access on every login. Dovecot's image now includes `curl`, and `AETHER_API_INTERNAL_URL` (default `http://api:8080`) tells Dovecot where the API is.
- Import mail from another provider: **Settings → Import mail** signs in to any IMAP account and copies its folders into a mailbox in the background, keeping flags and dates, mapping Sent, Drafts, Junk, Trash and Archive to their Aether folders, and skipping messages already present. Imports from servers on private addresses are blocked unless `AETHER_WEBHOOK_ALLOW_PRIVATE` is `true`.
- Distribution lists: an alias created with `kind` set to `list` takes up to 5,000 destinations, including other lists and outside addresses, and has a name that appears in the organization directory. `acceptFrom` limits who may send to it: anyone, people signed in to the organization, the list's own members, or an allow-list of addresses and `@domain` entries. Postfix checks restricted lists during the SMTP session by asking the API on a new internal port, 10040 (`AETHER_POLICY_LISTEN`; Postfix connects to `AETHER_POLICY_SERVICE`, default `api:10040`), and rejects other senders with `5.7.1`. `sendAs` names the mailboxes that may send as the list, and owners may change its destinations without being administrators.
- SCIM `/Groups`: an identity provider can create, rename, fill and delete groups at `/api/v1/scim/<slug>/Groups`, including `PATCH` with `add`, `remove` and `members[value eq "…"]` paths.
- Distribution lists can take their members from identity provider groups (`groups`) and from every personal mailbox on chosen domains of the organization (`memberDomains`), resolved when mail is delivered, so people join and leave with no change to the list. A list now needs at least one destination, group or domain instead of at least one destination. `members`-only lists accept mail from these members too. `GET /api/v1/aliases/{aliasId}/members` and **Show members** in **Administration → Aliases** show everyone a list reaches and how, and `GET /api/v1/organizations/{orgId}/directory-groups` lists the groups an administrator can choose.
- Recurring mail imports for migrations: an import can repeat every 1 to 10080 minutes until it is stopped or reaches an end time, copying only new mail on each run and reporting what it copied. Administrators schedule and stop imports for up to 100 mailboxes at once under **Administration → Mail imports** or with `/api/v1/organizations/{orgId}/import-schedules`, and mailbox owners from **Settings → Import mail**. Source passwords are stored encrypted and erased when a schedule ends. A schedule can also apply flag changes and deletions from the source to the messages it copied. See [Recurring mail imports](documentation/integrations.md#recurring-mail-imports).
- Distribution lists: an alias created with `kind` set to `list` takes up to 5,000 destinations, including other lists and outside addresses, and has a name that appears in the organization directory. `acceptFrom` limits who may send to it: anyone, people signed in to the organization, the list's own members, or an allow-list of addresses and `@domain` entries. Postfix checks restricted lists during the SMTP session by asking the API on a new internal port, 10040 (`AETHER_POLICY_LISTEN`; Postfix connects to `AETHER_POLICY_SERVICE`, default `api:10040`), and rejects other senders with `5.7.1`. `sendAs` names the mailboxes that may send as the list, and owners may change its destinations without being administrators. Moderation and members taken from identity provider groups are not built.
- Aliases and lists can be changed in place with `PATCH /api/v1/aliases/{aliasId}`: destinations, replaced or added and removed one at a time, the active state, kind, name, sender restrictions, send-as and owners. Each change is one `alias.update` audit event with the old and new values.
- Mail rules can test the body, any named header, the size in kilobytes, and whether the mailbox's address is missing from To and Cc. Text conditions can be negated, and a rule can delete a message instead of moving it.
- Organization administrators and API keys with `mailboxes:write` can manage delegates, mail rules, automatic replies and signatures for any mailbox in the organization, and import an iCalendar or vCard file into the mailbox owner's calendar or address book with `POST /api/v1/mailboxes/{mailboxId}/calendar/import` and `/contacts/import`.
- `DELETE /api/v1/organizations/{orgId}/members/{userId}` removes a member, together with their delegated mailbox access and list ownership in that organization. The last owner cannot be removed. API keys need `members:write`.
- Folder management in Aether Mail and the API: create, rename, move, delete (with an option to move the messages elsewhere first), empty and mark all as read, for the owner and full delegates. Special-use folders cannot be renamed or deleted, and renaming a folder updates the mail rules that file into it.
- Sorting and filtering the message list by date, sent date, sender, recipient, subject or size, in either direction, with filters for unread, flagged, attachments, sender, recipient and a date range. Aether Mail remembers the choice per folder.
- Moving and copying messages between a person's own mailbox and the mailboxes they have full access to, keeping headers, the original date and flags. Moves out of or into another mailbox are recorded in the audit log.
- Branding per organization under **Administration → Branding**: name, logos for light and dark themes, favicon, sign-in message, theme colours and custom CSS. The sign-in page uses the branding of the organization that owns the domain it is served on. `AETHER_CUSTOM_CSS=false` turns custom CSS off.
- Signature templates per organization and per domain under **Administration → Signatures**, with placeholders for name, job title, phone, organization, domain and address, the organization's links, and its own logo. Job title and phone can be set under **Settings → Profile**.
- Shared mailboxes: a mailbox created with `kind` set to `shared` has no account and no sign-in, only members with full or read-only access and separate Send as and Send on behalf rights. Members see it under their own folders in Aether Mail and as `Shared/<address>/` in mail apps, signed in as themselves; Dovecot enforces read-only access there too. Sent copies go to the shared Sent folder, and Send on behalf adds a `Sender` header with the member's address. `POST /api/v1/mailboxes/{mailboxId}/convert` turns a user mailbox into a shared one and back; converting to shared deprovisions the owner account when it signs in with the mailbox address, ends its sessions and revokes every app password for the mailbox, and converting back restores that account. Removing a member or lowering their rights takes effect at once and ends their open IMAP sessions; removing a person from the organization, suspending their account or revoking a delegated app password does the same, including sessions opened for delegated mailboxes with an app password or an identity provider access token. Converting a user mailbox to shared ends every session of the former owner, including those held as a delegate elsewhere, revokes every app password of a deprovisioned account and reconciles its other shared memberships. Deactivating or deleting a shared mailbox removes the members' rights from Dovecot first and answers `503 mail_unavailable`, changing nothing, when Dovecot cannot be reached; only then is the mailbox closed or deleted and are the members' sessions ended. Reactivating writes the current members' rights back and always succeeds; a background worker finishes the job if Dovecot is unreachable at that moment. The worker serves the longest-waiting mailbox first and backs off one whose reconciliation keeps failing, after 15 seconds, then 1 minute, then every 5 minutes, so one broken mailbox does not delay the others; a reconciliation that loses its lease to another process stops at once and schedules another pass, a reconciliation paused past its command limit cannot write a stale command when it resumes, a mailbox that changes while it is being reconciled queues behind the others instead of ahead of them, and a membership change made through the API waits at most 60 seconds for Dovecot before leaving the rest to the worker. Session kicks are recorded in the database, one per address, and retried until Dovecot confirms them. Replying to an invitation from a shared mailbox needs a sending right, and a scheduled message is sent only while its sender is active and still holds the right it was scheduled with. The account deprovisioned by a conversion cannot be reactivated until the mailbox is converted back. Delegates of user mailboxes gained the same `sendAs` and `sendOnBehalf` fields: existing full delegates received Send as, read-only delegates did not. See [Shared mailboxes](documentation/shared-mailboxes.md).
- The spam filter learns from Junk moves in every mail app: Dovecot's `imapsieve` plugin sends a message moved into Junk to Rspamd as spam, and one moved out of Junk, except to Trash, as not spam. Aether Mail has **Report spam** and **Not spam** buttons that do the same. Mail from someone in the recipient's contacts, or a reply to a message the recipient sent, stays out of Junk unless it scores 10 or more or fails DMARC. Learning can be turned off per organization under **Administration → Spam filter** or with `PATCH /api/v1/organizations/{orgId}` (`spamLearning`), and `aether_spam_learned_total` counts learned messages by class and result. See [Architecture](documentation/architecture.md#spam-filtering-and-learning).
- Organization mail flow rules under **Administration → Mail flow** and `/api/v1/organizations/{orgId}/mail-flow/rules`, applied by Postfix to every message the organization sends or receives, from any mail app. Conditions test the sender or recipients (address, domain, inside or outside the organization, member of a list), subject, body, a header, attachment names and types, size, spam score and direction; exceptions skip a rule. Actions append a text and HTML disclaimer, with a choice for signed or encrypted mail, copy or redirect to addresses, reject with a custom message, add or remove headers, change the spam score, require TLS for delivery and hold messages for approval by members of the organization, who decide under **Settings → Messages held by mail flow rules**. Rules run in order, can stop later rules, and can run in test mode, which only records what they would have done under **Recent matches**. Each change is an audit event with the old and new rule. API keys use the new `mailflow` scope. See [Mail flow rules](documentation/mail-flow-rules.md).
- Control over forwarding to outside addresses under **Administration → Forwarding** and `/api/v1/organizations/{orgId}/forwarding`: allowed, allowed only to listed domains, or blocked. Forwarding inside the organization is always allowed. The API refuses rules that break the policy, leaves blocked destinations out of the Sieve script, and recompiles affected mailboxes when the policy changes; Postfix's sieve relay port now asks the policy service about each recipient and rejects blocked forwards with `5.7.1`. Rule changes record `rule.forwarding.add` and `rule.forwarding.remove` with the destination in the audit log and webhooks, and the tab lists every mailbox that forwards outside the organization and where to.
- Message trace under **Administration → Message trace**: search mail by sender, recipient, subject, Message-ID, date and status, and follow each message from arrival (client address, TLS, spam score) to its outcome per recipient: delivered, filed in Junk, forwarded, deferred, bounced or rejected, with the other server's reply. Organization administrators see only their own domains' recipients and the mail their users sent; platform administrators can search the whole server. Results export as CSV, recorded in the audit log as `message_trace.export`. The API is `GET /api/v1/organizations/{orgId}/message-trace` with `/export` and `/{id}`, and `/api/v1/admin/message-trace` for platform administrators; API keys need the new `message-trace:read` scope. A new `mail-trace` service (`aether mail-trace`, a sidecar of Postfix in Helm) reads the Postfix log, including rotated copies, into PostgreSQL (migration 0032) and keeps records for `AETHER_MAIL_TRACE_RETENTION_DAYS` days, 30 by default. Postfix now logs each message's subject and the spam headers Rspamd adds. See [Message trace](documentation/message-trace.md).
- Moderation for distribution lists: with `moderated` set, messages from anyone but the moderators, owners and the senders in `moderationExempt` are held until a moderator approves them under **Settings → Messages waiting for approval**. `moderators` names the people who decide, and the owners do when it is empty. Moderators get an email with links to the message; rejecting one tells the sender, with an optional reason, and a message nobody decides on is discarded after five days with a notice to the sender. Each decision is recorded as `alias.message_approve` or `alias.message_reject`. Approved and exempt messages go to the list's current members, including those from groups and domains, in batches whose progress is saved, so a failed delivery is retried only for the members it has not reached. The API now receives `AETHER_SIEVE_RELAY_PASSWORD` in Compose and Helm to deliver approved mail on internal port 10025, and the Helm NetworkPolicy lets it reach that port. See [Distribution lists](documentation/architecture.md#moderation).
- Rooms and equipment with booking rules: a mailbox of the kind `resource` is a room or a piece of equipment with a name, seats, location and description, managed under **Administration → Rooms and equipment** or with an API key holding `mailboxes:write`. Invitations to it are answered automatically: accepted when it is free and the rules allow it, and declined, with the reason, when it is busy or breaks a rule. Rules cover how many days ahead it can be booked, the longest booking, set hours on chosen days in the room's time zone, and who may book, everyone in the organization or selected people. With approval turned on, requests wait for approvers, who get an email and decide under **Calendar → Requests**. Aether Calendar has a finder that shows which rooms are available for an event and why the others are not; invitations from Aether Calendar are answered while the event is saved, and invitations from other calendar apps are read from the room's inbox every 30 seconds. Rooms appear in the directory and in free/busy, and attendees that are rooms are marked with `CUTYPE=ROOM` or `RESOURCE`. Postfix now asks the policy service about mail to rooms as well and refuses mail that claims an Aether address without signing in. Migration 0040 adds the tables and lets a calendar belong to a mailbox instead of a person. See [Rooms and equipment](documentation/rooms-and-equipment.md).
- CalDAV scheduling for free/busy: every principal advertises a schedule inbox, a schedule outbox and its calendar user addresses, and a `POST` of a `VFREEBUSY` request to the outbox answers with the busy times of people and rooms in the same organizations. Calendar collections advertise `calendar-schedule`, which Thunderbird needs to find the outbox; apps keep sending invitations by email, and the outbox refuses anything but free/busy requests.
- Tagged addresses: mail to `name+tag@example.com` can go to the Inbox (the default), into a folder named after the tag, created when missing, into that folder only when it already exists, or be refused with `5.1.1` during the SMTP session. Choose under **Settings → Mail rules and automatic replies → Tagged addresses**, or as an administrator under **Administration → Mailboxes**, or with `PUT /api/v1/mailboxes/{mailboxId}/tagged-mail`. In the folder modes, a tag with characters other than letters, digits, hyphens and underscores goes to the Inbox. A tag on an alias is passed on to the mailboxes it delivers to and filed by their setting; only a tag on a mailbox's own address is refused, and a refusing mailbox gets aliased tagged mail in its Inbox.
- Personal aliases: under **Settings → Personal aliases** people create their own aliases, or generate a masked address in one click, on the domains an administrator allows and up to a limit per person set under **Administration → Aliases → Personal aliases**. Each one forwards only to a mailbox its creator owns, can carry a note and an expiry date, and can be turned off, which rejects mail sent to it with `550 5.1.1` and stops sending as it. Administrators see every personal alias with its owner and can delete it, and every change is in the audit log. Password managers such as Bitwarden can create masked addresses through the SimpleLogin-compatible `POST /api/alias/random/new` with a revocable key from Settings. Single sign-on and SCIM no longer create a mailbox at an address a personal alias holds; the account is created without it. See [Personal aliases](documentation/personal-aliases.md).
- Sending from aliases and lists in Aether Mail. The From menu lists, next to the mailboxes a person may send from, every alias that forwards to their mailbox and every list whose `sendAs` names it, and each address has its own From name and signatures under **Settings → Signatures**. A reply starts from the address the message was delivered to, even when it was in Bcc. A list can file sent copies in a shared mailbox under **Save sent copies in** (`sentMailboxId`); otherwise they go to the Sent folder of the sender's mailbox. `GET /api/v1/me/mailboxes` returns `fromAddresses`, and send, draft and scheduled messages and `/api/v1/mailboxes/{mailboxId}/signatures` take `fromAddress`. See [Sending from aliases and lists](documentation/architecture.md#sending-from-aliases-and-lists).
- Coexistence for migrations: a verified domain can name the old server's SMTP host under **Administration → Domains → Configure coexistence** or with `PUT /api/v1/domains/{domainId}/coexistence`. Mail for addresses that are not on Aether is then relayed to that host on port 25 instead of being rejected, and selected mailboxes can also receive a copy there (dual delivery). Relayed mail carries an `X-Aether-Coexistence` loop header that Postfix rejects if the message comes back. Turning coexistence on or off is audited, and domains with it on show a warning in the console. Postfix needs the new image and migration 0049. See [Coexistence during a migration](documentation/installation.md#coexistence-during-a-migration).
- Addresses that fail to sign in with 10 different passwords within 10 minutes, on IMAP, SMTP submission, ManageSieve, CalDAV and CardDAV or the web, are blocked for 15 minutes, doubling for each repeat within a day up to 24 hours. Dovecot checks each login with the API through its authentication policy. Platform administrators can see and lift blocks under **Administration → Blocked addresses**. `AETHER_AUTH_BLOCK_THRESHOLD` changes the threshold (0 turns blocking off) and `AETHER_AUTH_BLOCK_ALLOW_NETS` lists networks that are never blocked, by default loopback and the private ranges. New metric `aether_auth_address_blocks_total`; `aether_auth_attempts_total` also counts mail logins. See [Blocking repeated failed sign-ins](documentation/authentication.md#blocking-repeated-failed-sign-ins).
- Storage use and quota warnings. Aether Mail shows how full the mailbox is under the folder list, a banner once it passes the organization's first warning level, and **Settings → Storage** with the size of every folder and **Empty** for Trash and Junk. The API measures every mailbox through the doveadm HTTP API every `AETHER_QUOTA_CHECK_INTERVAL` (default `5m`) and puts one warning into a mailbox's Inbox as it passes each level, 80% and 95% unless an owner or administrator changes them under **Administration → Mailboxes → Storage warnings**, optionally with a copy to the organization's administrators. The mailbox list in Administration shows each mailbox's usage, and **Change quota…** edits a mailbox's quota. Folders gained `size`, mailboxes in the organization list `usedBytes`, and `GET`/`PUT /api/v1/organizations/{orgId}/quota-warnings` read and change the levels. Migration 0053 adds the columns. See [Storage and quota warnings](documentation/storage.md).
- Sender warnings in Aether Mail: an External tag on mail from outside the organization, a "You don't often get email from …" tip for new senders, and a warning when an outside sender uses a colleague's name, puts one of the organization's addresses in their name, writes from a look-alike domain, or uses the organization's domain without being sent through Aether or passing DMARC. **Sender verification** under the recipients explains the SPF, DKIM and DMARC results in plain words. Owners and administrators turn the tag, the tip and the warnings on or off under **Administration → Sender warnings** or with `GET` and `PUT /api/v1/organizations/{orgId}/sender-warnings`; all are on by default, and changes are audited as `sender_warnings.update`. `GET /api/v1/mailboxes/{mailboxId}/messages/{uid}` returns the verdict as `sender`. Rspamd records the results in a new `X-Aether-Authentication` header, which Postfix removes from incoming mail and imports remove from imported mail, so a sender cannot forge it. See [Sender warnings](documentation/sender-warnings.md).
- Two gauges for the access workers that every API process runs: `aether_mail_kick_backlog_seconds` reports the age of the oldest IMAP session kick that Dovecot has not confirmed yet, and `aether_mail_acl_backlog_seconds` the age of the oldest active mailbox whose members' rights are still waiting to be written to Dovecot, both 0 when nothing is pending.
- Allowed and blocked senders. Administrators list email addresses, domains and IP addresses for the whole organization or one domain under **Administration → Senders**, with an optional note and expiry date. Blocked senders are rejected during the SMTP session, and allowed senders skip spam filtering when the message passes DMARC for the header From or SPF for the envelope sender, but not virus scanning or a DMARC `reject` policy. People block senders and domains from the message view and keep blocked and trusted senders per mailbox under **Settings → Blocked and trusted senders**: blocked mail is deleted on arrival, and trusted mail goes to the inbox instead of Junk. Both lists are available through the API, with a new `senders` scope for API keys, and every change is recorded in the audit log. See [Architecture](documentation/architecture.md#allowed-and-blocked-senders).
- Recover deleted items: messages that are permanently deleted, by emptying Trash or Junk, deleting a folder, the automatic Trash and Junk clean-up or a mail app that expunges straight away, are kept in a hidden folder outside the quota for 1 to 30 days, set per organization under **Administration → Mailboxes** (default 14). People restore them to the folder they came from through **Recover deleted items** in the Trash menu, and administrators from a mailbox's **More actions** menu; restores and administrator views are recorded in the audit log. The API has `GET /api/v1/mailboxes/{mailboxId}/recoverable`, `POST /api/v1/mailboxes/{mailboxId}/recoverable/restore` and `PATCH /api/v1/organizations/{orgId}` with `deletedItemRetentionDays`. Draft versions, moves and deletions through `Shared/` in a member's own mail app are not kept. See [Recovering deleted mail](documentation/deleted-items.md).
- Compliance, for organizations with legal or regulatory duties ([Compliance](documentation/compliance.md)). Owners can make a member a compliance administrator, a new right separate from the existing roles. Compliance administrators create cases with a saved search over chosen mailboxes, domains or the whole organization by sender, recipients, subject, body, attachment name and dates; export the matches as `.eml` files or mbox in a ZIP with a `manifest.csv` of SHA-256 sums; place mailboxes on hold; and journal mail to or from an address or domain to an archive address. A hold keeps every message, or only those matching the case's search terms, attachment name and dates, checked the same way as a search: retention policies and the clean-up of recoverable items skip them, mail the person deletes, drafts included, stays in their recoverable items where they cannot remove it, and deleting the mailbox keeps it as an inactive, retained mailbox whose mail can still be searched. Searches and exports include recoverable items. Every case change, hold, search, export and journal rule is recorded in the audit log, and these `compliance.*` events are not sent to webhooks. The person is not told about a hold.
- Mailbox access auditing: with **Administration → Audit log → Mailbox access** turned on, Aether records when a delegate, a shared mailbox member or an administrator opens a folder, reads, moves, copies or deletes a message, sends as or on behalf of the mailbox, or changes its folders, rules, automatic reply or signatures, with the person, folder, subject and Message-ID, client and IP address. Actions in Aether Mail are recorded by the API, actions in mail apps by Dovecot, which now reports IMAP events to the API, and SMTP sends from a delegated or shared address by a new header-only milter that Postfix calls on `api:10047`. Organizations choose whether to include reads and the owner's own deletions, how long to keep entries, and whether owners may see who accessed their mailbox. **Access report** in a mailbox's menu lists who accessed it in a period, also at `GET /api/v1/mailboxes/{mailboxId}/access-log`. See [Mailbox access auditing](documentation/mailbox-auditing.md).
- Directory controls: **Hide from directory** on mailboxes, shared mailboxes and distribution lists (`hiddenFromDirectory` on `PATCH /api/v1/mailboxes/{mailboxId}` and on aliases) leaves the address out of the directory, address suggestions and CardDAV while it keeps receiving mail. Organization contacts, outside addresses with a name, company and phone number, are managed under **Administration → Contacts** or `/api/v1/organizations/{orgId}/contacts` (API keys need `contacts:read` or `contacts:write`), appear in every member's directory and address suggestions, and can be list members. CardDAV apps get the directory as a read-only address book named Directory.
- Outbound routing per domain under **Administration → Outbound routing**, for platform administrators: a relay host with optional credentials for each hosted sender domain, a fixed `[host]:port` transport for each outside recipient domain, and a TLS policy (`none`, `may`, `encrypt`, `dane`, `verify` or `secure`, with optional certificate hostnames) for each recipient domain or fixed endpoint. A recipient transport takes precedence over a sender relay, and mail that matches neither uses the global relay or direct delivery as before. Rules are stored in PostgreSQL and read by Postfix through views; relay credentials are encrypted with `AETHER_SECRET_KEY`, never returned by the API, and handed to Postfix by the API on a new internal port, 10041 (`AETHER_OUTBOUND_SASL_LISTEN`; Postfix connects to `AETHER_OUTBOUND_SASL_SERVICE`, default `api:10041`). The API now needs `AETHER_MAIL_DB_PASSWORD`, which Compose and the Helm chart pass to it. Authenticated relays, global or per sender, always require TLS, and a TLS policy for them can only make it stricter. See [Outbound routing](documentation/installation.md#outbound-routing).

- Sending limits per organization, domain and mailbox under **Administration → Sending** and `/api/v1/organizations/{orgId}/sending-limits`: messages an hour (default 200) and a day (1,000), recipients per message (100) and a day (2,000), first-time recipients a day (off), and the share of the day's mail Rspamd scores as spam (50%, from 10 messages). Postfix checks them on submission through the policy service on port 10040. An account that goes over a limit, other than recipients per message, is restricted: its outgoing mail is refused with `5.7.1` until an administrator releases it from the console or with `DELETE /api/v1/mailboxes/{mailboxId}/sending-restriction`. Restricted senders are listed at `/api/v1/organizations/{orgId}/restricted-senders`. Restrictions and passing 80% of a limit are recorded as `mailbox.sending_restricted` and `mailbox.sending_limit_near`, sent to webhooks and put in the inbox of each owner and administrator.
- Attachment filtering per organization under **Administration → Attachments** and `GET`/`PUT /api/v1/organizations/{orgId}/attachment-policy`: separate lists of blocked file types for incoming and outgoing mail, each set to reject the message during the SMTP session, remove the attachment and leave a note, or off, plus exempt senders. Rspamd matches the file name, the type detected from the content and the names inside ZIP, 7z and gzip archives. By default incoming mail with executables, scripts, disk images and macro-enabled Office files is rejected; outgoing mail is not checked. See [Attachment filtering](documentation/installation.md#attachment-filtering).
- Booking pages: each user can publish a public scheduling page at `/book/<slug>` from **Calendar → Booking page**, with configurable meeting types (duration, buffers before and after, weekly availability windows, target calendar, location, and video link), minimum notice, booking horizon, and host timezone. Open slots are computed from the host's own non-subscribed calendars, and confirming a booking creates the calendar event under a per-host lock and emails an iTIP invitation to the guest.
- Calendar subscriptions: subscribe to external `https://` or `webcal://` iCalendar feeds under **Calendar → Calendars**. Feeds refresh on a configurable schedule (using `If-None-Match` and `If-Modified-Since`), appear read-only in Aether and over CalDAV, cannot be shared with write access, block private network addresses unless `AETHER_WEBHOOK_ALLOW_PRIVATE` is `true`, and report refresh outcomes in `aether_calendar_subscription_refresh_total`.
- Tasks (`VTODO`) in Calendar and over CalDAV: create, edit, filter, prioritize, set due dates, and complete tasks in the Calendar **Tasks** view, synced over CalDAV alongside calendar events.
- Account security notifications: people receive an email alert (delivered directly to their Inbox) and an in-app list under **Settings → Security** when an app password is created for their mailbox, an external-forwarding mail rule is added, someone is given delegate access, their account signs in from a new device or country, or repeated failed sign-ins occur. Each alert includes links and actions to review or undo the change (revoking the app password, removing the external forwarding address, removing the delegate, or signing out that session) or report suspicious activity to organization administrators (`security.notification.report` in the audit log and webhooks, plus admin email). Organization administrators can choose which events notify, set the failed sign-in threshold, and choose whether to also notify administrators under **Administration → Security**.

### Changed

- Inbound mail scoring 15 or more, or rejected by an Rspamd rule or ClamAV, is now accepted and held in quarantine instead of rejected, and mail scoring from 10 to 15 is held instead of filed into Junk. Rspamd falls back to rejecting or to Junk when the API is unreachable. Rebuild or pull the `rspamd` image with this release. The Helm NetworkPolicy now admits Rspamd to the API on port 8080.
- Dovecot runs a per-mailbox `aether-senders` Sieve script before the spam-to-Junk script and enables the `editheader` extension. Postfix asks the API about every recipient on port 25, and Rspamd calls the API at `AETHER_API_INTERNAL_URL` (default `http://api:8080`); the Helm NetworkPolicy now admits Rspamd to the API on port 8080.
- Postfix now passes mail on ports 25, 587 and 465 through two milters in the API, on internal ports 10045 (`AETHER_MILTER_LISTEN`, before Rspamd) and 10046 (`AETHER_MILTER_AFTER_LISTEN`, after it). Postfix connects to `AETHER_MILTER_SERVICE` and `AETHER_MILTER_AFTER_SERVICE` (defaults `api:10045` and `api:10046`) and answers `451` while the API cannot be reached, so mail waits instead of skipping the organization's rules. The API now also receives `AETHER_SIEVE_RELAY_PASSWORD`, to send on approved messages through Postfix port 10025 (`AETHER_SIEVE_RELAY_ADDR`, default `postfix:10025`); the Helm chart lets the API reach that port. Migration 0030 adds the rule, match and held message tables.
- Dovecot's SQL password lookup now calls the `aether_mail_login` function added by migration 0037, and the access token check passes Dovecot's session ID to the API, so that a delegate signed in as another mailbox can be told apart from the owner. Over SMTP, a delegate who signs in as the delegated mailbox with an app password or access token is now authenticated as their own address, which keeps Send as to that mailbox but no longer allows sending as other addresses through its credentials. Upgrade the API before Dovecot and Postfix. The Helm chart's NetworkPolicy now admits Dovecot to the API on port 8080.
- `POST /api/v1/auth/login` answers with `twoFactor` instead of a session for accounts with two-factor authentication; finish with `POST /api/v1/auth/login/two-factor`. Changing a password, an administrator setting one, and `aether bootstrap-admin` now end the account's other web sessions.
- New mailboxes and aliases cannot contain a plus sign, which marks a tag. Mail to an existing alias that contains one still reaches that alias. An existing mailbox whose address contains a plus sign never received its own mail, because Dovecot reads the part after the plus sign as a tag; rename it. Dovecot now sets `lmtp_save_to_detail_mailbox = yes`, and Postfix removes the tag for mailboxes that keep tagged mail in the Inbox, so their delivery does not change.
- The fixed Rspamd rate limit of 200 messages an hour per sender (`ratelimit.conf`) is removed; the configurable sending limits replace it. Postfix submission now calls the API's policy service for every recipient, so the API must be reachable from Postfix for mail to be sent.
- Dovecot allows 100 IMAP connections per user per IP, up from 50, so live mail can hold IDLE connections beside ordinary webmail requests.
- **Breaking:** `DELETE /api/v1/mailboxes/{mailboxId}` removes the mailbox's mail from disk. It needs Dovecot to be reachable when the mailbox is still open; otherwise it answers `503 mail_unavailable` and changes nothing. A grace period or a hold answers `200` with the mailbox instead of `204`.
- **Breaking:** `AETHER_DOVECOT_API_KEY` is a new required secret, given to the API and Dovecot only, never to Postfix, for the doveadm HTTP API on internal port 8089. `scripts/setup.sh` generates it for new installations; existing installations must add it to `.env` before upgrading, because Compose refuses to start without it. The Helm chart generates `dovecotApiKey` in its Secret.
- **Breaking:** `AETHER_RSPAMD_CONTROLLER_PASSWORD` is a new required secret, given to the API and Rspamd only, that lets the API train the spam filter through Rspamd's controller. `scripts/setup.sh` generates it for new installations; existing installations must add it to `.env` before upgrading, because Compose refuses to start without it. The Helm chart generates `rspamdControllerPassword` in its Secret, exposes the controller port 11334 to the API, and now lets Dovecot reach the API on port 8080.
- Dovecot now loads the ACL plugin and a shared namespace with the prefix `Shared/`. A pre-existing top-level folder named `Shared` becomes unreachable in mail apps after the upgrade; check with `doveadm mailbox list -A 'Shared*'` first and rename any it lists. Dovecot restarts during the upgrade, which briefly disconnects IMAP clients.
- Issuing an app password, an Apple profile or an OIDC-token IMAP login for a delegated mailbox now requires full access with Send as, which every existing full delegate has.
- Automatic replies can be read and changed by organization administrators and by people with Send as on the mailbox, and changing them also needs full access; other delegates get `403 cannot_send`.
- Messages scheduled before this upgrade are marked with an error by migration 0023 and are not sent. Cancel them to get the drafts back and schedule them again.
- Account email addresses may not contain `*` or `?`: SCIM answers `400 invalidValue`, single sign-on does not provision such an address, and migration 0025 refuses to apply while an existing account has one. Dovecot treats those characters as wildcards when ending sessions.
- Dovecot loads the `lazy_expunge` plugin with a hidden `.EXPUNGED/` namespace stored in `Expunged/` in each mailbox's home directory, and reads a global ACL from `/etc/dovecot/dovecot-acl`. Disk use grows by the mail deleted during the retention period. Migration 0035 adds `deleted_item_retention_days` to `organizations`. Dovecot restarts during the upgrade.
- Migration 0036 adds the `mail_userdb` and `mail_journal` views. Dovecot now looks users up in `mail_userdb`, which also lists disabled mailboxes that are on hold and turns off recoverable item expiry, the `\Drafts` exclusion and expunging of recoverable items for held mailboxes through `/etc/dovecot/dovecot-acl-held`, and Postfix reads journal rules from `mail_journal`. Upgrade the API first so the migration runs before Dovecot and Postfix restart with the new queries; until then, mail logins fail and Postfix cannot look up journal rules.
- Deleting a mailbox that is on hold answers `200` with the retained mailbox instead of `204`, and deleting a retained mailbox that is still held answers `409 mailbox_retained`.
- Deleting a domain that still has mailboxes, active or not, answers `409 domain_not_empty` instead of deleting them with it; delete the mailboxes first. Migration 0026 makes the database refuse such a deletion as well, for domains and organizations.
- Dovecot no longer adds its growing per-address delay after failed logins, which reached 15 seconds for every login from that address and made Postfix answer `454` to everyone behind a shared address. Failed attempts are still delayed by 2 seconds, and repeated failures are now handled by blocking. The Helm chart's network policy now lets Dovecot reach the API on port 8080, which access-token logins already needed.
- Deactivating or deleting a shared mailbox answers `503 mail_unavailable` when the members' rights cannot be removed within 60 seconds, not only when Dovecot is unreachable.
- Postfix's recipient check also reads the new `mail_unavailable_personal_aliases` view, and migration 0046 turns `mail_aliases` and `mail_senders` into views over the previous ones, renamed `mail_alias_routes` and `mail_sender_grants`. Rebuild and restart Postfix with this release.
- Postfix delivers to Dovecot over a new `mailbox-lmtp` transport, one recipient per LMTP transaction, so that every delivered copy carries an `X-Original-To` header. Rebuild the Postfix image when upgrading.

- **Breaking:** the message list pages with an opaque `cursor` instead of `before`, and `nextCursor` is now a string. Clients that page with `before` must pass the returned `nextCursor` as `cursor`.
- The organization signature template no longer contains the Scala Studios logo. Each organization sets its own.

- The SPF check evaluates the record as a receiving server would, for every address of the mail host, following `include`, `redirect`, `a`, `mx`, `ip4`, `ip6` and `exists` within the limit of 10 DNS lookups. A record that authorizes the server through an `include` or an IP address now shows **OK**. Softfail, neutral and records that cannot be evaluated show **Not strict**, and only a `fail` shows **Mismatch**.

### Fixed

- Saving a distribution list with an empty `owners` list now removes every owner instead of keeping them.

## 0.1.0 - 2026-10-16

The first release. Container images are published to GitHub Container Registry as `ghcr.io/scalastudios/aether-<component>:0.1.0` for `api`, `web`, `postfix`, `dovecot`, `rspamd` and `unbound`.

### Added

- A mail server on one Docker host: Postfix for inbound SMTP on port 25 and submission on 465 and 587, Dovecot for IMAP on 143 and 993, and Rspamd as a milter, all configured from PostgreSQL by the Go API.
- Domains, mailboxes, aliases, catch-all addresses, distribution lists and quotas, managed per organization, with domain ownership verification.
- Sender-login enforcement on both the envelope and the From header, SRS for aliases that forward outside, and refusal of open relaying.
- Spam filtering with DNS blocklists through a bundled Unbound resolver, spam filed into Junk, DKIM signing with a 2048-bit RSA key per domain, ARC signing, outbound rate limits, and optional ClamAV scanning.
- DNS records for every domain with a live check, MTA-STS policies, TLS reporting, DMARC aggregate reports summarized per sending address, and DANE checks on outbound mail.
- Mail app setup: Thunderbird autoconfig, Autodiscover XML, RFC 6186 SRV records, and an Apple configuration profile with mail, calendar and contacts accounts.
- Aether Mail: folders, conversations, server-side search, rich-text compose with a formatting toolbar, signatures with an organization template and inline images, attachments, drafts, scheduled send, snooze, keyboard shortcuts, and HTML mail rendered with remote content blocked.
- Mail rules and automatic replies compiled to Sieve, and shared mailboxes with full or read-only access.
- Calendar and contacts in the web app and over CalDAV and CardDAV: repeating events, ICS import and export, meeting invitations, shared and organization calendars, free/busy, a personal address book and the organization directory.
- Sign-in with local accounts (Argon2id) or any OpenID Connect provider with PKCE, a Halo setup wizard, group-to-role mapping, accounts created on first sign-in, suspension through signed Halo webhooks, and profile pictures imported from the identity provider.
- Mailbox-scoped app passwords for IMAP, SMTP, CalDAV and CardDAV.
- An admin console with organizations, domains, mailboxes, aliases, members, identity providers, DMARC reports, API keys, signed webhooks and an audit log.
- A REST API described by an OpenAPI 3.1 document, and organization API keys with scopes.
- Prometheus metrics for the API, Postfix, Dovecot and Rspamd with a Grafana dashboard, and OpenTelemetry tracing for the API.
- Backup and restore scripts, with encrypted off-site copies to S3-compatible storage through restic.
- A Helm chart that validates in CI.
